# Progreso: cuentas-y-categorias
- Siguiente: 3.20 RED — mismo archivo `src/app/(privado)/cuentas/estados.test.tsx`, test "Error al cargar las cuentas ofrece reintentar" (pulsar "Reintentar" llama a `retry`).
- Decisiones: cada ciclo RED/GREEN/REFACTOR va en un commit con la suite en verde; el RED se registra en el cuerpo del commit. Las mutaciones se hacen con `docker exec cuadre-db psql` sobre `cuadre_test` y se restauran antes del commit. Tests de aislamiento entre usuarios: el segundo usuario se crea con `crearUsuarioSinCategorias` (`src/test/bd/usuarios.ts`), sin seed. Pantalla de cuentas: `ul` con `aria-label="Cuentas"` solo si hay cuentas; estado vacío enfoca `nombre` vía `formularioRef`; región `aria-live` siempre presente; la fila de `estado.idCreado` lleva `animate-resaltado`; `revalidatePath('/cuentas')` tras crear; `key` = `JSON.stringify(estado)` en el formulario; esqueleto en `loading.tsx` con `aria-busy`.
- Discrepancias: el pre-commit ejecuta la suite completa, así que un RED no puede commitearse solo. El hook bloquea escribir archivos nuevos en `prisma/migrations/`. Las mutaciones que quitan `usuario_id` del índice rompen también el registro de los tests de 2.28, que usan seed.
