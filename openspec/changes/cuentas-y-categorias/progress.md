# Progreso: cuentas-y-categorias
- Siguiente: grupo 4 (verificación). 4.1 es [HUMANO]: con `docker compose up -d` y `npm run dev`. 4.2 ejecutar `npm run lint`, `npx tsc --noEmit`, `npm run test:run` y `openspec validate cuentas-y-categorias --strict`. Pendiente de decisión del humano antes de empezar el grupo 4.
- Decisiones: cada ciclo RED/GREEN/REFACTOR va en un commit con la suite en verde; el RED se registra en el cuerpo del commit. Las mutaciones se hacen con `docker exec cuadre-db psql` sobre `cuadre_test` y se restauran antes del commit. Tests de aislamiento entre usuarios: el segundo usuario se crea con `crearUsuarioSinCategorias` (`src/test/bd/usuarios.ts`), sin seed. Pantallas de cuentas y categorías: mismo patrón (`pantalla.ts`, `page.tsx`, `loading.tsx`, `error.tsx`, `Contenido*.tsx`, `Formulario*.tsx`), con región `aria-live`, fila resaltada, `revalidatePath`, `key` por respuesta y error por campo.
- Discrepancias: el pre-commit ejecuta la suite completa, así que un RED no puede commitearse solo. El hook bloquea escribir archivos nuevos en `prisma/migrations/`. Las mutaciones que quitan `usuario_id` del índice rompen también el registro de los tests de 2.28, que usan seed. Los ciclos 3.27–3.32 van en un único commit porque comparten archivos de test. Los ciclos 3.39–3.43 de estados de categorías comparten archivo de test, y el RED del test de error se vio como fallo de importación del archivo completo.
